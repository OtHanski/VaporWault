`TASK-00292` adds the wire capability to carry a `server_version` hint in
`HELLO_OK`/`VERSION_REJECT`, and the `vw_proto_negotiate` API to encode it,
but the server never actually populates it yet.

At `vw_server_conn_handle` (`vw_server_core.c:949`, negotiate call at `:963`),
pass the server's own `VW_VERSION_STRING` (already compiled into every
binary via `vw_version.h`) as the `server_version` to encode into whichever
of `HELLO_OK`/`VERSION_REJECT` actually gets sent. This must work on **both**
paths — the ordinary successful-negotiation path and the version-rejected
path — since the rejected path is the more important one for a client that's
too old to even connect (see `TASK-00291`'s design notes on why).

## Acceptance criteria

- A client connecting to this server always sees `out_hint->present == 1`
  with the server's real version string, on both `HELLO_OK` and
  `VERSION_REJECT`.
- No wire/behavior change for a server-side negotiate call that's actually
  server-to-server (cluster links, `vw-cluster/1` ALPN) — confirm those call
  sites are unaffected or explicitly pass `NULL`/don't populate.
- Existing negotiation tests still pass; add one asserting the populated
  `server_version` matches `VW_VERSION_STRING`.
