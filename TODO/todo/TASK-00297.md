## Manifest schema (`update-manifest.json`, published by `TASK-00301`)

```json
{
  "schema_version": 1,
  "sequence": 7,
  "release_version": "0.4.2",
  "min_client_protocol_version": 6,
  "published_at": 1757900000,
  "assets": [
    { "platform": "linux",   "arch": "x86_64", "dist_kind": "portable", "filename": "vaporwault-v0.4.2-linux-x86_64.tar.gz",   "sha256": "..." },
    { "platform": "windows", "arch": "x86_64", "dist_kind": "portable", "filename": "vaporwault-v0.4.2-windows-x86_64.zip",     "sha256": "..." }
  ]
}
```

## Parser

Hand-rolled, scoped to exactly these 6 fields (not `vw_json.c` — see
`ARCHITECTURE.md`'s "Client auto-update: manifest parser" row for why). No
general-purpose JSON semantics needed: fixed key set, no nesting beyond the
one flat `assets` array, no need to handle arbitrary input shapes gracefully
beyond rejecting anything that doesn't match.

## Verify-then-parse pipeline

```c
vw_err_t vw_update_manifest_fetch_and_verify(vw_update_manifest_t *out);
```

Mandatory order, never reversed:
1. `vw_update_https_get("github.com", ".../update-manifest.json", ...)`
   (small cap, e.g. 64 KiB).
2. `vw_update_https_get(..., "update-manifest.json.sig", ...)` — the
   detached ECDSA signature (raw bytes, small cap).
3. `vw_crypto_ecdsa_p256_verify()` over `SHA256(manifest_bytes)` against
   `VW_UPDATE_MANIFEST_PUBKEY` — **fail closed** on any error.
4. Only then parse the now-trusted bytes with the hand-rolled parser.
5. Rollback check: read `update_last_seen_sequence` from
   `{state_dir}/daemon.conf`. If `manifest.sequence < persisted`, return
   `VW_ERR_UPDATE_MANIFEST_ROLLBACK` and do nothing further. Else,
   **immediately** persist `manifest.sequence` as the new ratchet value
   (before evaluating whether an update is actually relevant) — the ratchet
   only needs a validly-signed manifest to have been seen.

`published_at` is informational only — never used in a trust decision (no
clock-based logic anywhere in this pipeline, deliberately, to avoid
clock-skew bug classes).

## Acceptance criteria

- Unit tests: valid manifest+sig verifies and parses correctly; tampered
  manifest bytes (signature no longer matches) rejected before parsing ever
  runs; malformed JSON-shaped-but-wrong-schema payload rejected by the
  parser; a validly-signed manifest with `sequence` below a pre-seeded
  ratchet value rejected with `VW_ERR_UPDATE_MANIFEST_ROLLBACK`; ratchet
  correctly advances on a validly-signed higher-sequence manifest even when
  the caller never proceeds to install anything.
- Fuzz target for the hand-rolled parser (it will see attacker-influenced
  bytes, even though those bytes are signature-verified first — defense in
  depth, matches the project's existing fuzz-testing practice for protocol
  parsers).
- SEC.07 review: confirm verify-before-parse ordering is actually enforced
  in code, not just documented; confirm no path exists where parsed-but-
  unverified data is ever acted on.
