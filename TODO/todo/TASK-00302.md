Full audit of the new attack surface this milestone introduces — the
client's first-ever outbound connection to a non-VaporWault host, plus a
self-replacing install mechanism. Cover at minimum:

- Outbound TLS to a non-pinned host (`vw_update_net.c`): cert validation
  actually enforced (no silent fallback to unverified), redirect-loop
  bounding, response-size bounding, the Windows `CertOpenStore` shim.
- Hand-rolled HTTP/1.1 response parsing: malformed input handling, no buffer
  overflows on attacker-controlled `Content-Length`/headers.
- Hand-rolled manifest parser: fuzz-test results, verify-before-parse
  ordering actually enforced in code.
- ECDSA verify wrapper and the manifest signing scheme: rollback/sequence
  ratchet correctness, no TOCTOU between manifest verify and asset fetch.
- Self-replacing install logic on both platforms: `vapourwault-updater`'s
  target-directory/PID handling, no arbitrary-path or privilege-escalation
  angle, package-manager-owned files never touched (portable-vs-package
  detection's fail-safe default actually holds under adversarial conditions).
- `daemon.conf` policy toggle: can a local unprivileged process or a
  malicious IPC client flip `update_policy` or corrupt the ratchet value in
  a way that defeats rollback protection?
- The new `UPDATE_SIGNING_KEY`/GPG key custody in CI — confirm no key
  material is logged or left on disk after the job.
