`TASK-00287`'s investigation concluded a real, project-specific Android
release keystore is approved, even with no Play Store presence — free to
generate, meaningfully better than every contributor's shared Gradle
debug key. `docs/RELEASE.md`'s APK section already anticipated this
exact follow-up when `TASK-00239` first shipped the debug-signed
release-variant APK.

## Acceptance criteria

- A dedicated release keystore generated for this project (not reused
  from any contributor's local environment).
- `android/app/build.gradle`'s `release` build type switched from
  `signingConfigs.debug` to a new `signingConfigs.release` sourced from
  the keystore.
- Keystore + credentials (store password, key alias, key password) live
  only in GitHub Actions secrets, wired into `release.yml`'s
  `build-android` job — matching how `SDL2_ZIP_SHA256`/`WIX_ZIP_SHA256`-
  style supply-chain-sensitive material is already handled there, per
  `docs/RELEASE.md`'s own existing note.
- `docs/RELEASE.md`'s APK section updated: this is no longer "signed with
  the same debug key every contributor's local install generates" —
  describe the real signing identity (without exposing anything
  sensitive) and note this still doesn't change sideload-only
  distribution (no Play Store presence).
- Verify a real signed release build installs cleanly via `adb install`/
  direct sideload, not just that the build step succeeds.
- SEC.07 review before `done`, per the `security-sensitive` tag: key
  storage, scoping, and a rotation/backup story (an Android release
  keystore, unlike a GPG key, generally can't be rotated without losing
  update continuity for anyone who'd already installed a build signed
  with it — worth being explicit that this doesn't matter today since
  there's no update mechanism at all yet, but recording the tradeoff).
