Discovered while fixing `TASK-00265`'s CI-wiring gap for
`phase22-corruption-detection-repair` (PR #2): widening CI's cluster
pytest step to actually run `test_gateway_fallback.py` (previously
silently excluded — see `TASK-00265`) exposed that `.github/workflows/
ci.yml`'s `integration` job never passes `-DVW_BUILD_WEB_GATEWAY=ON` to
its CMake configure step. `VW_BUILD_WEB_GATEWAY` defaults `OFF`
(`CMakeLists.txt`), so `build/bin/vapourwault-web-gateway` never exists
in this job at all — every gateway-dependent test (`test_gateway.py`'s
whole suite, `test_gateway_fallback.py`'s three tests) has always
silently `SKIPPED` in CI via `binaries.require_gateway()`, never
actually run for real. Grepped every workflow file
(`ci.yml`/`release.yml`): `VW_BUILD_WEB_GATEWAY` appears nowhere at all.

This predates both `TASK-00265` and this session entirely — not a
regression introduced by Phase 22's work. Fixed the two
`test_gateway_fallback.py` tests that were missing their own
`binaries.require_gateway()` guard as an immediate, narrowly-scoped fix
(see that task's own follow-up note) so CI stays green; this task is the
separate, larger fix of actually building the gateway so these tests run
for real instead of perpetually skipping.

## Acceptance criteria

- `.github/workflows/ci.yml`'s `integration` job (or a dedicated new job,
  implementer's call) builds `vapourwault-web-gateway`
  (`-DVW_BUILD_WEB_GATEWAY=ON`) and passes `--gateway-bin
  build/bin/vapourwault-web-gateway` to whichever pytest step(s) need it.
- Confirm via a real CI run that `test_gateway.py` and
  `test_gateway_fallback.py`'s tests actually execute (not skip) and
  pass.
- Check whether building the gateway meaningfully increases this job's
  runtime or needs any additional system packages on `ubuntu-latest`
  beyond what's already installed for the rest of the `integration` job
  — disclose either way, don't just assume it's free.
