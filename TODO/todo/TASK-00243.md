`TASK-00235`'s `CoreFlowTest` automates login → browse → upload → download →
delete only. `TASK-00235`'s own acceptance criteria called for coverage of
the full "login→browse→transfer→vault→share path," but vault
(`VaultActivity`: create/unlock/browse/upload/download) and sharing/link
management (`SharesActivity` and the share/link dialogs added in
`TASK-00231`) ended up with zero instrumented coverage — disclosed as a gap
in `TASK-00235`'s closing notes rather than claimed as done.

Extend `android/app/src/androidTest/java/com/vaporwault/client/` with
additional test classes (reusing `TestServerConfig`/`UiTestHelpers` from
`TASK-00235`) covering:
- Vault: create a vault with a passphrase, upload a file into it, exit and
  re-unlock with the correct passphrase, verify the file is still there and
  byte-identical; a negative case with a wrong passphrase asserting it's
  cleanly rejected (matching the manual verification already done in
  `TASK-00230`, now automated).
- Sharing: grant a share to another account, verify it appears in
  `SharesActivity`'s share list, revoke it, verify it disappears (or is
  filtered — matching the existing revoked-share bug fix from `TASK-00231`).
- Public links: create a link (with and without a password/expiry), verify
  it appears in `SharesActivity`'s link list, revoke it.

This will also need a second real test account (or account state) for the
share-grant target, since `TestServerConfig` currently only configures one
account.

## Acceptance criteria

- Vault create/unlock/upload/download, including a wrong-passphrase negative
  case, is covered by an instrumented test.
- Share grant/list/revoke and link create/list/revoke are each covered by an
  instrumented test.
- All new tests pass against a real `vapourwaultd`, verified via server-log
  cross-reference the same way `TASK-00235`'s original suite was.
