Full-project review (`TASK-00269`) confirmed a disclosed limitation from
`TASK-00096`: the desktop GUI's "shared with me" view is a flat list —
there is no way to descend into a shared folder's subtree and browse its
contents, only see the top-level shared item itself. Fixing this needs a
protocol-level decision (a new message, or an extension to `FILE_LIST`
scoped by a shared folder's `file_id`/permission context), not just a GUI
change.

## Acceptance criteria

- Design published in `docs/PROTOCOL.md`, following this project's
  existing "purely additive, no protocol version bump unless an existing
  byte layout changes" convention wherever possible.
- Explicitly decide how permission checks apply to nested contents (does
  the outer share's permission level extend to everything inside, or can
  it be overridden per sub-item — check `effective_permission()`'s
  existing model in `vw_file_handlers.c` before designing a parallel one).
- No client/GUI implementation in this task — that's `TASK-00282`.
