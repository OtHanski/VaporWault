Full-project review (`TASK-00269`) found `TASK-00192`'s selective sync
(include/exclude rules) explicitly cannot reach inside a vault — vault
contents are treated as one atomic encrypted unit. This looks like a
likely-permanent consequence of the E2EE design (the client can't
selectively decrypt/sync part of a vault's content without the server or
some intermediary learning more about vault structure than the zero-
knowledge design intends), but it has never been recorded as an explicit
decision — it's a quiet limitation, not a confirmed tradeoff.

## Acceptance criteria

- A real decision, recorded in `ARCHITECTURE.md`'s Architectural Decisions
  table: either (a) confirm this is permanent and explain why (tie it to
  the actual E2EE design constraint, not just "it's hard"), or (b) if a
  workable design exists that doesn't compromise the zero-knowledge
  property, describe it and file follow-on implementation tasks.
- Either outcome closes the ambiguity — no more "quiet limitation with no
  written rationale."
