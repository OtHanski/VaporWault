New signature-verification primitive plus a new dedicated signing keypair for
the update-manifest scheme (`TASK-00291`). See `ARCHITECTURE.md`'s "Client
auto-update: manifest signing key" row for the full rationale (why a new key
distinct from the GPG packaging key, why ECDSA over GPG).

## New `vw_crypto` primitive

```c
#define VW_ECDSA_P256_PUBKEY_BYTES 65 /* uncompressed SEC1 point: 0x04||X||Y */

vw_err_t vw_crypto_ecdsa_p256_verify(const uint8_t pubkey[VW_ECDSA_P256_PUBKEY_BYTES],
                                      const uint8_t hash[VW_HASH_BYTES] /* SHA-256 digest */,
                                      const uint8_t *sig_der, size_t sig_der_len);
```

Implement via `mbedtls_pk_setup`/`mbedtls_ecp_point_read_binary`/
`mbedtls_pk_verify` (same `mbedtls_pk_ec()` accessor pattern `vw_acme.c:552`
already uses, same justifying comment carried over). Returns `VW_OK` on
match, `VW_ERR_CRYPTO_SIG_INVALID` (new error code, next free slot `611` in
the 600-block, `vw_proto.h`) otherwise — follows the `vw_crypto_argon2id_verify`
return-code convention, not a separate bool out-param.

Also add the update-engine's own local error codes (client/daemon-local,
next free slot in the 700-block after `VW_ERR_IPC_NOT_RUNNING = 700`):
`VW_ERR_UPDATE_MANIFEST_INVALID`, `VW_ERR_UPDATE_MANIFEST_ROLLBACK`,
`VW_ERR_UPDATE_NET`, `VW_ERR_UPDATE_ASSET_MISMATCH`.

## Keypair generation and custody

- New committed script `packaging/signing/gen_update_keypair.sh` (offline
  only, never run in CI): `openssl ecparam -name prime256v1 -genkey` +
  `openssl ec -pubout`.
- Private key (PEM) goes into a new GitHub Actions secret
  `UPDATE_SIGNING_KEY` — same custody pattern as the existing
  `GPG_SIGNING_PRIVATE_KEY`.
- Public key committed twice, kept in sync by a test:
  1. `packaging/signing/update-manifest-pubkey.pem` (human/auditor-readable).
  2. `src/core/vw_update_pubkey.h` — generated once, hand-committed
     `static const uint8_t VW_UPDATE_MANIFEST_PUBKEY[VW_ECDSA_P256_PUBKEY_BYTES] = {...};`
     (raw SEC1 point bytes), compiled directly into every client binary.
- New unit test parses the `.pem` at test time and asserts its decoded raw
  point bytes equal `VW_UPDATE_MANIFEST_PUBKEY`, so the two committed forms
  can never silently drift apart.

## Acceptance criteria

- `vw_crypto_ecdsa_p256_verify` unit-tested: valid signature accepts, flipped
  bit in signature/hash/pubkey rejects, malformed DER rejects, does not crash
  on truncated/garbage input.
- Keypair generated, private key added to GitHub Actions secrets (manual step
  — document exactly what the operator must do, since this agent cannot add
  repo secrets itself).
- Both committed public-key representations present and the drift-check test
  passes.
- SEC.07 sign-off given `security-sensitive` tag — this key's compromise
  would let an attacker sign a malicious update manifest.
