Extend the wire handshake so the client can learn the server's software
version, in both the normal-handshake case and the hard-rejection case. See
`TASK-00291`/`ARCHITECTURE.md`'s "Client auto-update: version exchange" row
for the full rationale.

## Wire layout

`HELLO_OK` (`vw_proto.h:395-398`, currently 18 bytes: `negotiated_version` u16
+ `server_id[16]`): append, only when `total_len > 18`:
- `update_ext_ver` (u8) — `1` for this design; a reader seeing a higher value
  it doesn't understand treats the block as absent.
- `server_version_len` (u8), `0..31`.
- `server_version` (ASCII, not NUL-terminated), `server_version_len` bytes.

Max extended size 51 bytes — inside the client's existing 64-byte read buffer.

`VERSION_REJECT` (`vw_proto.h:400-403`, currently 4 bytes: `min_version`/
`max_version` u16 each): same trailing block appended at offset 4. Max
extended size 37 bytes.

`HELLO` (client→server) is deliberately **unchanged** — only the server's
version is exchanged in v1.

No `VW_PROTO_VERSION_CURRENT` bump — this is a purely additive extension,
same precedent as `TASK-00106`/`TASK-00186`.

## API change

`vw_proto_negotiate()` (`vw_proto.c:165`, declared `vw_proto.h:668`) gains a
new optional out-parameter:

```c
typedef struct {
    int  present;
    char server_version[32]; /* NUL-terminated; "" if !present */
} vw_proto_update_hint_t;

vw_err_t vw_proto_negotiate(vw_conn_t *conn, int is_server,
                             uint16_t *out_version,
                             vw_proto_update_hint_t *out_hint /* may be NULL */);
```

Critical detail: the client branch must populate `*out_hint` **before**
returning, on *both* the `VW_OK` (`HELLO_OK`) path and the
`VW_ERR_PROTO_VERSION` (`VERSION_REJECT`) path — `vw_client_sess_t` is
destroyed on the reject path before the caller ever sees it, so the hint
cannot live inside the session object. Bounds-check `server_version_len <= 31`
and against the buffer's actual received length before copying.

Server branch never populates `out_hint` (nothing to report about itself in
this direction); server callers pass `NULL`.

Update the 5 call sites: `vw_client_core.c:207,238,258,2223` (client, each
needs a new trailing `vw_proto_update_hint_t *out_hint` parameter threaded
through their own public signatures, may be `NULL`) and
`vw_server_core.c:963` (server, passes `NULL`) — actually wiring the server's
own `server_version` into the *sent* `HELLO_OK`/`VERSION_REJECT` is
`TASK-00294`'s job, not this task's; this task only adds the wire
encode/decode capability and the negotiate API.

`docs/PROTOCOL.md`: new dated revision entry documenting the extension, the
`update_ext_ver` versioning-of-the-extension convention, the 64-byte
compatibility ceiling, and that `HELLO` is intentionally unchanged.

## Acceptance criteria

- Old client ↔ new server: old client's fixed-size read + `plen < N` check
  already tolerates the extension untouched — verify with a real
  old-binary-vs-new-server test, not just code inspection.
- New client ↔ old server: `out_hint->present == 0`, no behavior change.
- `docs/PROTOCOL.md` revision entry published.
- Unit tests for the new encode/decode + bounds checks (malformed
  `server_version_len`, oversized value, truncated payload).
