Advisory (non-blocking) items from `TASK-00085`'s review, deferred to avoid
scope creep on that task:

1. **Real cluster integration test.** `tests/integration/test_cluster.py` is
   a gated placeholder (`pytestmark = pytest.mark.cluster`, skipped unless
   `VW_TEST_CLUSTER=1`, body is `assert True`). `TASK-00085` fixed two bugs
   that made real replication impossible and validated the fix manually
   (two real `vapourwaultd` processes, `cluster node-add` +
   `cluster register-self`, confirmed `NODE_HELLO OK` + oplog pull) — but
   there's still no automated regression test for any of it. Per
   `CLAUDE.md`, every resolved SEC.07 finding should have a corresponding
   regression test; write one covering at minimum: successful pairing,
   oplog replication advancing `sync_watermark`, and auth failure on a
   wrong/missing token.
2. **CLI naming symmetry** (`src/server/vw_server_cli.c` usage text) —
   `cluster node-add`/`cluster register-self` (nested subcommand) vs
   `cluster-status` (flat hyphenated) is inconsistent. Consider `cluster
   status` for symmetry (breaking change to the CLI surface — coordinate
   with anyone already scripting against it, but nothing ships yet).
3. **Duplicated disk-write logic** — `vw_cluster_node_add` and
   `vw_cluster_node_add_self` (`src/server/vw_cluster.c`) share ~20 lines of
   append/sync/index-update/error-cleanup logic verbatim. Factor into a
   shared static helper to avoid future divergent bugs (exactly the kind
   `TASK-00085` just fixed).
4. **Unbounded `node_id` from admin input** — `handle_node_register_self`
   (`src/server/vw_admin.c`) passes a client-supplied `node_id` straight to
   `index_ensure`, which doubles its capacity array up to that value with no
   ceiling. Low severity given the trusted local-only admin channel, but a
   typo'd huge value could trigger a large allocation. Add a sanity ceiling
   (e.g. reject `node_id` above some reasonable bound like 2^20).

QA.06 [2026-07-30]: Addressed all four items.

**1. Real cluster integration test** (`tests/integration/test_cluster.py`,
rewritten — the old file was a `pytestmark`-gated placeholder that always
passed trivially). Adds a `ClusterNode` helper (mirrors `conftest.py`'s
`ServerInstance` but with `cluster_port`/`cluster_is_replica`/
`cluster_primary_host`/`cluster_primary_port` config, each node getting its
own free client port and cluster port) and three real tests, all standing
up two actual `vapourwaultd` processes:
- `test_pairing_registers_both_sides`: runs `cluster node-add` on the
  primary + `cluster register-self` on the replica (the exact two-step
  operator flow `docs/TUTORIAL.md` documents), confirms each side's
  `cluster status` shows the pairing from its own perspective (`replica`
  role on the primary, `self` role on the replica).
- `test_oplog_replication_advances_sync_watermark`: after pairing, creates
  a user on the primary (append an oplog entry) and polls the primary's
  `cluster status` until `sync_watermark` for the replica's node advances
  above 0 — this is the actual replication path working end to end, not
  just pairing.
- `test_wrong_auth_token_never_replicates`: pairs with a deliberately wrong
  `auth_token`. Confirmed by reading `src/server/vw_admin.c`'s
  `handle_node_register_self` that `NODE_REGISTER_SELF_REQ` only creates a
  local record on the replica — it does not itself validate the token
  against the primary; that happens later, when the replica's poll thread
  sends `NODE_HELLO` to the primary's cluster port
  (`vw_cluster.c`). So this test confirms register-self still succeeds
  locally (matching production behavior — a wrong token isn't detectable
  until the wire handshake), then confirms `sync_watermark` never advances
  and the primary's log contains `"NODE_HELLO auth failed"` (the exact
  `CL_WARN` message `vw_cluster.c`'s `NODE_HELLO` handler emits on a token
  mismatch) — i.e. the auth boundary is actually enforced, not merely
  assumed. Server stdout+stderr are redirected to a per-node log file
  (readable while the process is still running) rather than
  `subprocess.PIPE`, since these tests need to inspect log content without
  tearing the server down.

Wired into CI as its own step in `.github/workflows/ci.yml`
("Run pytest cluster integration tests", `-m cluster`) rather than folding
into the main `-m "not cluster"` step — pairing + polling for replication
makes this run noticeably slower (~25s locally for all three) than the rest
of the suite. This satisfies the acceptance criterion that these run by
default in CI rather than only on manual opt-in.

**2. CLI naming symmetry.** Added `cluster status` (nested, under the
existing `cluster` subcommand dispatch in `src/server/vw_server_cli.c`) as
a symmetric alias alongside `cluster node-add`/`cluster register-self`.
Did **not** remove the original flat `cluster-status` spelling: the task's
own acceptance criteria conditioned a breaking rename on "nothing ships
yet", but `v0.1.0` is now an actual tagged release (see git log) —
removing a v0.1.0-documented command for pure ergonomic symmetry would
break any existing script for zero functional gain, so both spellings are
kept indefinitely, with `cluster status` as the documented/preferred form
going forward. Updated `docs/TUTORIAL.md` and `docs/DEPLOYMENT.md` to use
`cluster status`; the CLI's own `--help`/usage text documents
`cluster-status` explicitly as "Alias for 'cluster status' (v0.1.0
spelling)" so the relationship is clear from `--help` alone.

**3. Duplicated disk-write logic.** Factored the shared append/sync/
index-update tail of `vw_cluster_node_add` and `vw_cluster_node_add_self`
(`src/server/vw_cluster.c`) into a new static `node_append_and_index()`
helper. Callers still own locking/error-path zeroing of `auth_token` (that
part differs enough between the two — one returns the token to the caller,
the other never does — that folding it in too would obscure more than it'd
save), but the ~14 duplicated append/sync/index lines are now one shared
6-line function.

**4. Unbounded `node_id`.** Added `VW_CLUSTER_MAX_NODE_ID` (2^20) in
`vw_cluster.c` and a check in `vw_cluster_node_add_self()` (the one that
takes a client-supplied `node_id`, via `handle_node_register_self` over the
local admin socket) rejecting anything above it with `VW_ERR_INVALID_ARG`
before it ever reaches `index_ensure()`.

**Validation:** rebuilt clean on both platforms (GCC via WSL Ubuntu,
