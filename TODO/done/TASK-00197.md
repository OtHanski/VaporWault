Publish the wire spec for `TASK-00196`'s filename search feature.

**Correction (2026-08-26)**: `TASK-00196`'s cursor-pagination decision
assumed an existing convention this protocol doesn't have — checked
`docs/PROTOCOL.md` directly; every existing list response
(`FILE_LIST_RESP`/`SHARE_LIST_RESP`/`LINK_LIST_RESP`) returns its whole
result set in one response with a hard entry cap, no cursor anywhere.
Work section below replaced accordingly (no pagination — a cap +
`truncated` flag, matching the real existing convention).

## Work

- New opcode pair `SEARCH`/`SEARCH_RESP` (pick the next free opcode block
  after the existing highest-numbered messages, following this project's
  numbering convention).
- `SEARCH` payload: `session_token[32]` + query string (length-prefixed;
  reject oversized queries with `VW_ERR_INVALID_ARG` before any table
  scan, not after). No scoped-session support in v1 — a `LINK_ACCESS`
  -redeemed anonymous session already sees only one subtree it can
  browse directly, so "search everything visible" doesn't add anything
  for it; reject with the same "authenticated session required" posture
  `SHARE_GRANT`/`LINK_CREATE` already use for scoped sessions
  (§7.5's "Grant/link operations require a real authenticated session").
- `SEARCH_RESP` payload: `error_code`(u32) + `count`(u32) +
  `truncated`(u8, 1 = more matches existed than the cap allowed) +
  `count` repetitions of `{file_id(u64), name(string, leaf, display-only
  — same convention as `SHARE_LIST_RESP`'s own `name` field), is_dir(u8),
  size(u64), mtime(i64), vault_id(u64), is_shared(u8)}`. No virtual path
  in either direction: an owned match's path is reconstructable by the
  caller via repeated `FILE_STAT_BY_ID`/parent lookups if truly needed,
  and a shared match has no meaningful path in the caller's own
  namespace at all (fabricating one would mean either guessing at the
  owner's directory structure above the shared root, which the grantee
  was never shown, or inventing a "path" that isn't real) — `file_id`
  already round-trips through every existing file-id-addressed
  operation (`TASK-00095`/`00106`), which is enough to act on a result.
  `is_shared` (`effective_permission() != VW_PERM_OWNER`) lets the
  client show "somewhere in a folder shared with you" without needing a
  path.
- Permission section (§ the table listing `FILE_LIST`/`FILE_STAT`/etc.
  under `VW_PERM_VIEW`): add `SEARCH` alongside them — it is a read,
  scoped to what the caller can already see.
- Error codes: reuse existing ones (`VW_ERR_INVALID_ARG` for a malformed/
  oversized query) rather than inventing new ones unless a real gap
  surfaces during implementation.

## Acceptance criteria

- SRV.01 and WEB.09 can implement against this section without further
  clarification.
- No existing message's byte layout changes.
