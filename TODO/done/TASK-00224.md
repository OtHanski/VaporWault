Kick off the Android client effort (user request, 2026-08-31): a Drive-like
app (browse, upload/download files and folders, manage profile(s)) speaking
`vw/1` directly, consistent with the project's minimal-dependency/low-level
philosophy.

Decided with the user before this task was written:
- Native JNI reuse of the existing C client-core, not a Kotlin reimplementation
  of the wire protocol, not routing through the web gateway's HTTP/JSON API.
- Classic Android Views, not Jetpack Compose.
- Vault/E2EE support is in scope for the first milestone, not deferred.
- Scope: on-demand browse/upload/download (Drive/Proton-Drive-app style), not
  the desktop client's continuous background folder-mirroring — this follows
  from the user's own "in likeness to Google Drive/Proton Drive" framing, and
  removes `vw_sync`/`vw_daemon`/`vw_ipc`/`vw_watch_*` from scope entirely
  (Android has no persistent-daemon equivalent to run them in anyway).
