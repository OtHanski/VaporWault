Discovered out-of-domain while implementing `TASK-00262` (QA regression
coverage for Phase 22's corruption-repair pipeline): `.github/workflows/
ci.yml`'s "Run pytest cluster integration tests" step runs

```
pytest tests/integration/test_cluster.py -v -m cluster ...
```

— explicitly scoped to `test_cluster.py` only, not `tests/integration/`.
Every OTHER `cluster`-marked test in a different file is therefore never
run in CI at all: the main "Run pytest integration tests" step excludes
them (`-m "not cluster"`), and the cluster step never looks at their
files. This predates `TASK-00262` — confirmed by inspection that
`test_cli_fallback.py`, `test_cli_version_fallback.py`, and
`test_gateway_fallback.py` (all pre-existing, all `pytestmark = [pytest.
mark.cluster, ...]`) have the exact same gap. `TASK-00262`'s new
`test_corruption_repair.py::test_replica_repair_when_local_reconstruction_
impossible` (`@pytest.mark.cluster`) is the newest test to fall into it,
not the first.

This is a real coverage gap, not merely a cosmetic one: a regression in
any of these four files' `cluster`-marked tests would currently go
unnoticed by CI. Confirmed to matter concretely during `TASK-00262`
itself — the new cluster test caught (and this pass then fixed) a real
bug in `vw_cluster.c`'s `repair_slots` cleanup that none of the
in-process C tests happened to exercise (see `TASK-00262`'s own closing
notes and `vw_cluster.c`'s `handle_cluster_conn` for the fix); a coverage
gap of this shape is exactly the kind of thing that lets a bug like that
sit undetected in CI indefinitely.

## Acceptance criteria

- CI runs every `cluster`-marked test across `tests/integration/`, not
  just the ones in `test_cluster.py` — e.g. by changing the existing
  cluster step's target from `tests/integration/test_cluster.py` to
  `tests/integration/` (keeping `-m cluster`), or another equivalent fix.
- Confirm via a real CI run (or a local `pytest tests/integration/
  -m cluster` invocation matching the intended CI command) that all four
  currently-orphaned files' cluster tests are now collected and pass.
- No double-execution of `test_cluster.py`'s own tests introduced as a
  side effect (i.e. don't end up running that file's tests in both the
  main "not cluster" step, which shouldn't happen given the marker, and
  a broadened cluster step — just confirm this explicitly since the fix
  touches shared CI plumbing).
