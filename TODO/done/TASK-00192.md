`ARCHITECTURE.md` has claimed for some time that `vw_cache` owns
"selective-sync rules" (letting a user include/exclude subfolders from a
sync folder). This was already flagged in the 2026-08-05 audit note as a
claim with **no corresponding code anywhere** — not a stale-but-once-true
claim, a claim that was never real. This task designs the feature for
real and corrects the doc (`TASK-00204` handles the broader doc audit;
this task's own Decision Log row supersedes the `vw_cache` claim
specifically).

## Decisions

1. **Entirely client-local, no protocol change.** Selective sync is "the
   client chooses not to request/apply certain remote paths it already
   knows about via `FILE_LIST`" — it needs no new server capability.
   PRT.04 is not blocking this.
2. **Rule shape**: per sync folder, a list of glob-style exclude patterns
   (relative to the sync folder's root, `fnmatch`-style — same mental
   model as `.gitignore`, deliberately not full `.gitignore` semantics
   like negation, to keep the matcher small and pure-C). No separate
   "include" list — everything not excluded is included (simpler mental
   model, matches what most competing products actually ship despite
   calling it "selective sync").
3. **Ownership**: rules live on `vw_sync_folder_t` (not `vw_cache` — that
   module never had this and the claim was fictional) and persist in
   `account.conf` alongside the folder's other config (local path,
   `remote_dir_id`, paused flag).
4. **Enforcement point**: `vw_sync.c`'s BFS collect step
   (`srv_collect`/its `remote_dir_id`-rooted variant from `TASK-00106`)
   skips any remote entry whose relative path matches an exclude rule —
   it is never added to the local action list, so it's never downloaded
   and never deleted locally if it already exists (see next point).
5. **Existing local files when a rule is added**: excluding a path that
   is already synced locally does **not** delete the local copy — it
   just stops pulling further remote changes into it and stops pushing
   local changes for it upstream. Silently deleting a user's local files
   because they added a filter is the kind of surprising, destructive
   behavior CLAUDE.md's general engineering guidance warns against; an
   explicit "remove local copies of excluded files" action can be a
   separate, deliberate button, not an implicit side effect. Confirmed as
   the right default without needing to ask the user, since it's a
   conservative default that no rule change can make worse than the
   alternative.
6. **Conflict with vault folders**: vault-rooted sync folders (`TASK-00098`
   -`101`) are exempt — a vault's contents are one encrypted-blob-managed
   unit; partial exclusion inside a vault is out of scope here.
