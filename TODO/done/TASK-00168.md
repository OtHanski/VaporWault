Full-feature integration coverage for `TASK-00160`'s multi-account design,
once every implementation task above has landed.

## Tests to add

- **Daemon concurrent multi-account sync** (`tests/integration/`, C, mirror
  the existing `test_shared_sync*.c` real-client/real-server style): two
  accounts configured on one daemon instance against two real test-server
  users; drive file changes on both server sides; confirm both accounts'
  local caches converge without either being queried as "active" via
  `ACCOUNT_LIST_REQ`/file-list calls in between — proves sync isn't gated
  on which account a UI happens to be looking at.
- **Gateway multi-slot switching** (`tests/integration/test_gateway.py`):
  one `requests.Session` logs into two slots as two different users;
  interleave authenticated calls against both via `X-Vw-Slot`; confirm
  each slot's calls only ever see that slot's own account data (no
  cross-slot leakage).
- **Remember-me resume-after-restart** (`tests/integration/test_gateway.py`
  or a new script if the existing gateway fixture can't cleanly kill+
  relaunch the gateway process mid-test): log in with `remember: true`,
  kill the gateway process, relaunch it against the same `--state-dir`,
  present the same cookie again, confirm a 200 (not 401) and that the
  session actually works (e.g. a `list_files` call succeeds) without
  resending credentials.
- **Resume-rotation race**: after a simulated restart (or forced pool
  eviction), fire two near-simultaneous requests presenting the same
  stale remembered cookie; confirm exactly one succeeds and the other gets
  a clean 401 (not a crash, not a corrupted on-disk store — read the store
  back afterward and confirm it has exactly one valid rotated entry, not
  two conflicting writes).
- Regression test for every SEC.07 finding raised during `TASK-00161`/
  `TASK-00165`'s review, per `CLAUDE.md`'s standing rule that every resolved
  SEC.07 finding gets a regression test.
