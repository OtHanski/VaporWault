`TASK-00255`'s scrub thread runs on its own schedule (default every 6
hours) with no way for an operator to trigger a pass on demand or check
the results of the last one. Add admin IPC messages and CLI subcommands
for both, following the exact `handle_reload_cert`/`handle_cluster_status`
pattern already established in `vw_admin.c`.

## Acceptance criteria

- `VW_ADMIN_SCRUB_RUN_REQ`/`_RESP` (0x9019/0x901A): runs one full scrub
  pass synchronously and returns its counts.
- `VW_ADMIN_SCRUB_STATUS_REQ`/`_RESP` (0x901B/0x901C): reports the most
  recently completed pass's counts/timestamp without running a new one.
- `vapourwault-server-cli scrub run` / `scrub status` subcommands,
  matching the existing `cluster status` / `reload-cert` command style
  and `usage()` text.
- Both admin messages return `VW_ERR_INVALID_ARG` if the scrub module is
  unavailable (mirrors the existing `cluster`/`node-add` pattern for an
  unavailable subsystem).
