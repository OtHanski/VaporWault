User request: when a client connects to a server running a newer release, the
server should tell the client, and the client should (as automatically as
reasonably possible, with real care for attacker-controlled attack surface)
fetch and install the matching release from GitHub Releases and restart
smoothly.

Two scope decisions confirmed with the user up front:

- **Self-install v1 scope**: automatic self-replacing update only for the
  portable Linux `.tar.gz` / Windows `.zip` distribution. `.deb`/`.rpm`/`.msi`
  installs get a notification + link only — never an attempted
  `pkexec`/`sudo`/`msiexec` invocation, never touching files the client
  doesn't know it owns.
- **Consent policy**: default is "notify + one-click confirm" in the GUI; a
  settings toggle offers an opt-in "fully automatic" policy for
  hands-off/headless setups.

A follow-up scope extension was also confirmed: GPG-sign every release asset
(not just `.deb`/`.rpm` as today), restructured into the `publish` CI job for
a single key import (`TASK-00304`).

## Design (full detail in `ARCHITECTURE.md`'s new Architectural Decisions rows)

- **Protocol**: additive trailing block on `HELLO_OK`/`VERSION_REJECT`
  (`update_ext_ver`, `server_version_len`, `server_version`), no new message
  type, no `VW_PROTO_VERSION_CURRENT` bump. Verified both existing readers
  (`vw_proto.c`) already tolerate trailing bytes. `TASK-00292`.
- **Trust model**: server-advertised version is only ever a trigger hint. The
  client independently fetches a small, fixed-schema, ECDSA-P256-signed
  `update-manifest.json` from a fixed GitHub Releases URL
  (`releases/latest/download/update-manifest.json`), verifies the signature
  over the manifest's raw bytes before parsing, checks a monotonic `sequence`
  ratchet against replay/rollback, then downloads the actual asset from the
  manifest's own signed, version-pinned URL (never `latest` a second time —
  avoids a TOCTOU race) and checks its SHA-256. `TASK-00293`, `TASK-00297`.
- **New crypto primitive**: `vw_crypto_ecdsa_p256_verify` in `vw_core`, a new
  dedicated ECDSA P-256 keypair distinct from the existing GPG packaging key,
  public key compiled into the client binary. `TASK-00293`.
- **New client capability**: the client's first-ever outbound HTTPS client to
  a non-VaporWault host (`vw_update_net.c`, TLS 1.3 + minimal HTTP/1.1 GET,
  real OS trust store — not a pinned PEM), plus a hand-rolled manifest parser
  scoped to 6 known fields (deliberately not reusing the gateway's
  `vw_json.c`). `TASK-00296`, `TASK-00297`.
- **Self-install**: `.vw-portable` marker file (added to tarball/zip staging
  only, no `CMakeLists.txt install() changes needed — confirmed by reading
  `release.yml`), fail-safe toward "not portable" (notify-only) if absent. A
  new standalone `vapourwault-updater` helper handles the actual file swap +
  relaunch on both platforms (one mechanism, not two divergent ones), invoked
  by the daemon after it reuses its *existing* graceful-shutdown path.
  `TASK-00295`, `TASK-00298`.
- **IPC/GUI**: new `0x8051`–`0x8056` IPC pair range, GUI banner + settings
  toggle reusing existing idioms (`render_offline_banner`,
  `BeginPopupModal`). `TASK-00299`, `TASK-00300`.
- **CI**: manifest generation/signing + all-asset GPG signing in
  `release.yml`. `TASK-00301`, `TASK-00304`.
