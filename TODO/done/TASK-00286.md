Full-project review (`TASK-00269`) found `TASK-00192`'s selective sync
(include/exclude rules) explicitly cannot reach inside a vault — vault
contents are treated as one atomic encrypted unit. This looks like a
likely-permanent consequence of the E2EE design (the client can't
selectively decrypt/sync part of a vault's content without the server or
some intermediary learning more about vault structure than the zero-
knowledge design intends), but it has never been recorded as an explicit
decision — it's a quiet limitation, not a confirmed tradeoff.

## Acceptance criteria

- A real decision, recorded in `ARCHITECTURE.md`'s Architectural Decisions
  table: either (a) confirm this is permanent and explain why (tie it to
  the actual E2EE design constraint, not just "it's hard"), or (b) if a
  workable design exists that doesn't compromise the zero-knowledge
  property, describe it and file follow-on implementation tasks.
- Either outcome closes the ambiguity — no more "quiet limitation with no
  written rationale."

ARCH.00 [2026-09-11]: **Decision: this was never a live ambiguity — it
was already resolved by `TASK-00193`, just never reflected in
`ARCHITECTURE.md`.**

Before writing a new decision, checked whether one already existed:
`TASK-00192`'s original design (decision 6) proposed exactly the framing
this task's own filing repeated — "vault-rooted sync folders are exempt,
partial exclusion inside a vault is out of scope." But `TASK-00193`'s own
implementation notes found and struck that decision as describing
something that doesn't exist: vault content has never been registered as
a `vw_sync_folder_t` at all. `VAULT_UPLOAD`/`VAULT_DOWNLOAD` are manual,
one-file-at-a-time operations that never touch the automatic sync
engine's folder/exclude-rule machinery — `vw_view_vault.cpp`'s own header
comment states this plainly. So the real answer to "can exclude rules
reach inside a vault" is: there is no automatic vault sync for a rule to
apply to *at all* — not a cryptographic or zero-knowledge constraint on
selective decryption, as this task's own filing speculated.

`ARCHITECTURE.md`'s Selective-sync rules decision row still repeated the
struck "not available on vault-rooted sync folders" line — a live
doc-drift instance directly on point for `TASK-00277`'s own subject.
Corrected in place with the real explanation and a forward note: if
automatic vault-aware sync is ever built as a real feature, exclude-rule
interaction becomes a genuine open design question again at that point,
not before.

No follow-on implementation tasks — nothing to build, since nothing was
actually broken or missing once the premise was checked against source.
