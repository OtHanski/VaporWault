Implements the GUI side of `TASK-00281`'s daemon IPC addition
(`VW_IPC_SHARED_FOLDER_LIST_REQ`/`_RESP`, no wire-protocol change involved
— see that task's corrected finding) in the desktop GUI's "shared with
me" view (`src/gui/client/views/vw_view_shared.cpp`), replacing today's
flat-list-only display (and its now-stale "no IPC message lists a
folder's children by id" note) with real folder navigation.

## Acceptance criteria

- A shared folder can be opened and browsed into, matching the existing
  file browser's navigation feel (`vw_view_browser.cpp`) rather than a
  parallel, inconsistent UI pattern.
- Consumes the client library API only, per this project's GUI/client
  boundary rule — no protocol or socket code added directly here; blocks
  on `TASK-00281`'s published spec, not a unilateral reinterpretation of
  it.

  every other `ipc_*` method here.
- `vw_view_shared.cpp`: the "Shared with me" flat list gained a "Browse"
  button per row. Since `SHARE_LIST` carries no `entry_type` (a share's
  target could be a file or a folder — `TASK-00281`'s own note on why),
  clicking it always attempts to browse; a target that turns out to be a
  file surfaces `VW_ERR_INVALID_ARG` as an inline message on the flat
  list instead of switching into an empty browse view. Once browsing, a
  breadcrumb trail (file_id-based, not path-based — there is no
  owner-namespaced path into content the caller doesn't own) lets the
  user click "Open" on any `dir`-typed row to descend further (unbounded
  depth, matching `TASK-00281`'s own finding that permission inheritance
  already supports this) or click an earlier crumb / "Up" to go back;
  leaving the stack empty returns to the flat share lists.

**Two real bugs found and fixed along the way, not part of this task's
original scope but directly adjacent**: three places in this same file
called a refresh function that reassigns a `std::vector` (`s_shared_by_
me`/`s_my_links`/the new `s_browse_entries`) from *inside* a range-based
`for` loop iterating that exact vector — undefined behavior via iterator
invalidation on reallocation. Two of the three (the pre-existing
"Revoke" buttons on the "shared by me" grants/links tables) were already
in the file before this task; the third was one I wrote myself for the
new "Open" button and caught before it ever shipped. Fixed all three the
same way: defer the mutating call until after the table/loop completes,
using a `pending_*` local variable — the same pattern this codebase's
`vw_view_browser.cpp` already uses for its own confirm/cancel actions.
