User-requested scope extension (confirmed 2026-09-15): today only
`.deb`/`.rpm`/`linux-packages.sha256` get GPG-signed (existing ed25519 key,
`packaging/signing/vaporwault-releases-pubkey.asc`); the `tar.gz`, `zip`, and
`.apk` are only SHA-256-checksummed, unsigned. Close this gap using the same
existing key/infra.

- Extend GPG signing to produce a detached `.asc` for **every** release
  asset: Linux `tar.gz`, Windows `zip`, Android `.apk`, and
  `update-manifest.json` (which then ships with two independent sidecar
  signatures — `.sig`, ECDSA, verified automatically by the client per
  `TASK-00297`; `.asc`, GPG, for humans — complementary, not redundant; the
  client never parses GPG at runtime).
- **Restructure where signing happens**: move GPG signing entirely into the
  `publish` job, after it downloads all three platforms' artifacts into
  `dist/` (already does this) and before `gh release create`/`gh release
  upload`. The private key is then imported exactly once per release run
  instead of being duplicated across `build-linux`/`build-windows`/
  `build-android`.
- Does **not** address the Windows-unsigned-binary/SmartScreen risk — GPG
  signatures aren't recognized by Windows for execution trust; a paid
  Authenticode certificate would be needed for that, explicitly out of scope
  here (real recurring cost, a separate decision if ever pursued).
- `docs/RELEASE.md`: update verification instructions to cover the
  newly-signed asset types, and note that `update-manifest.json` carries two
  independent signatures for two independent purposes.

## Acceptance criteria

- Every asset in a real (or dry-run) release has a valid `.asc` signature
  verifying against the committed public key.
- GPG private key imported in exactly one job (`publish`), not three.
- `docs/RELEASE.md` updated.
- SEC.07 review of the restructured signing step (same bar as any CI secret
  handling change).

## Notes

**BLD.05 (2026-09-16):** Implemented.

- `build-linux` job: removed the "Import GPG release signing key" and
  "Sign .deb/.rpm packages" steps entirely (and dropped `*.asc` from the
  `linux-release` artifact's uploaded `path:` list) — signing moved out of
  this job per the restructure.
- `publish` job: added "Import GPG release signing key" and "Sign release
  assets with GPG" steps, placed after "Remove update-signing key"
  (`TASK-00301`'s ECDSA manifest-signing cleanup) and before "Create or
  update GitHub Release". The private key is imported exactly once for the
  whole run. Signs, via a `FILES_TO_SIGN` bash array + loop:
  the Linux `.tar.gz`, every `.deb`/`.rpm`, `linux-packages.sha256`, the
  Windows `.zip`, the Android `.apk`, and `update-manifest.json`. Key is
  discarded with `if: always()` immediately after signing, matching the
  Android keystore's and TASK-00301's ECDSA-key cleanup convention.
  `$TAG`/`$REPO` and the file paths are all sourced from workflow `env:`/
  prior-step outputs, never interpolated directly from a `${{ }}`
  expression into a shell string (TASK-081's discipline).
- Deliberately excluded from signing: `.msi` (Authenticode is the correct
  mechanism there, a separate already-recorded decision — GPG carries no
  Windows execution-trust meaning) and `windows-packages.sha256` (not
  requested; no `.sha256` verification story exists for Windows today,
  unlike Linux's). Flagged inline in the workflow and here for SEC.07/
  CQR.08 to weigh in on during review.
- `gh release upload`/`gh release create`: added `update-manifest.json.asc`
  explicitly to the uploaded-file list (alongside the pre-existing
  `update-manifest.json`/`.sig`); every other new `.asc` lands inside the
  already-wildcarded `dist/*-release/*` directories, so needs no separate
  listing.
- `docs/RELEASE.md`: rewrote the GPG section to describe the new
  centralized-in-`publish`, all-asset scope, updated the verification
  commands to include `tar.gz`/`zip`/`.apk`, documented the `.msi`/
  `windows-packages.sha256` exclusions, and added the required note that
  `update-manifest.json` now carries two independent signatures (`.sig`
  ECDSA, verified by the client at runtime; `.asc` GPG, for humans, never
  parsed by the client) for two independent purposes.
